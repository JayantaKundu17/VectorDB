TOPIC: Decision Trees
CATEGORY: decision_trees

DEFINITION
A decision tree recursively partitions data using feature-based rules to create homogeneous regions.

HOW IT WORKS
Splits can be chosen using criteria such as Gini impurity or entropy for classification and variance reduction for regression.

KEY IDEAS
The exact implementation depends on the model family, data type, objective, and operating constraints.
The main design variables are representation, objective function, optimization or search procedure, and evaluation criteria.

COMMON USE CASES
tabular data, interpretable rules, mixed feature types

ADVANTAGES / STRENGTHS
This approach is useful when its assumptions and inductive biases match the structure of the problem. It can provide a strong baseline, specialized performance, interpretability, efficiency, or scalability depending on the topic.

LIMITATIONS / FAILURE MODES
deep trees overfit and unstable splits can change with small data changes

COMPARISON
Decision Trees should be distinguished from random forest and gradient boosting. The best choice depends on data size, feature type, dimensionality, latency, accuracy, interpretability, and operational constraints.

EVALUATION / PRACTICAL CHECKS
Choose metrics that match the task and business cost of errors. Validate on a representative holdout or cross-validation design, check leakage, inspect failure cases, and monitor performance after deployment.

INTERVIEW TAKEAWAY
Be prepared to explain what Decision Trees is, how it works, when to use it, what assumptions it makes, and what trade-offs or failure modes it has.
