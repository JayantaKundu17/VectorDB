TOPIC: Data Cleaning
CATEGORY: data_cleaning

DEFINITION
Data cleaning identifies and corrects invalid, inconsistent, duplicated, missing, or corrupted records before modeling.

HOW IT WORKS
Cleaning should be based on domain rules and should be applied without leaking information from the test set into training.

KEY IDEAS
The exact implementation depends on the model family, data type, objective, and operating constraints.
The main design variables are representation, objective function, optimization or search procedure, and evaluation criteria.

COMMON USE CASES
nearly every ML project

ADVANTAGES / STRENGTHS
This approach is useful when its assumptions and inductive biases match the structure of the problem. It can provide a strong baseline, specialized performance, interpretability, efficiency, or scalability depending on the topic.

LIMITATIONS / FAILURE MODES
accidentally deleting signal, inconsistent rules, hidden leakage

COMPARISON
Data Cleaning should be distinguished from closely related approaches in the same problem family. The best choice depends on data size, feature type, dimensionality, latency, accuracy, interpretability, and operational constraints.

EVALUATION / PRACTICAL CHECKS
Choose metrics that match the task and business cost of errors. Validate on a representative holdout or cross-validation design, check leakage, inspect failure cases, and monitor performance after deployment.

INTERVIEW TAKEAWAY
Be prepared to explain what Data Cleaning is, how it works, when to use it, what assumptions it makes, and what trade-offs or failure modes it has.
